# Owner-controlled Google Drive backup

Version 0.4.5-drive-backup-preview (16) adds opt-in Drive app-data backup in Settings. Existing Google login is unchanged. AuthorizationClient requests only drive.appdata, pinned to the signed-in Google account. Tokens remain in memory and go only to Google APIs. Neither Cloudflare nor Gemini receives backup data.

The developer must enable Google Drive API in the same Google Cloud project as the Android OAuth client (existing web client project number 656908487206), configure the drive.appdata scope in OAuth consent, and make the app available to intended users/test users. Existing package name and permanent signing certificate must remain registered. These Cloud Console operations cannot be completed using the Cloudflare token or GitHub connection. No cloud secret is needed in the APK. Configure API: https://console.cloud.google.com/apis/library/drive.googleapis.com?project=656908487206 . Scope documentation: https://developers.google.com/workspace/drive/api/guides/appdata .

User flow: Google sign-in, Settings > Google Drive backup > options > enable. After consent, existing snapshots are listed, or the user confirms uploading current phone data. New phones choose an existing snapshot explicitly; local data is never silently replaced. Restore validates schema, signed-in owner and all bounds before writing, preserves the current configuration as an additional Drive snapshot first, rechecks local edits/account changes, and leaves all automatic-send permission/master settings unchanged.

Only reply_customization rules (including exact/allWords/enabled), instructions, facts, examples, fallback and fallback_enabled are included. No inbox, voice audio, ID/access tokens, permissions or API keys. Snapshots are immutable small JSON files (max 256 KB), never overwritten or automatically deleted. The latest 30 snapshots are offered for restore. History uses the owner’s Drive storage. Users can remove the entire app-data history through Google Drive Settings > Manage apps; disconnecting or deleting local app data does not delete these remote copies.

After each explicit template/configuration save, a network-constrained persisted JobScheduler job attempts backup after a short debounce. Network failures retry with backoff. Pending revision and last successful upload are visible in Settings. Android may defer background work, force-stop blocks work until reopening, and no data is protected until a successful upload. Revoked consent requires a new user grant. Account sign-out/change cancels backup; re-enabling explicitly confirms where current phone data will go. Older snapshots remain available if devices edit independently; this is versioned backup, not live cross-device merging.

Validate in local/unit and CI checks; do not mark cloud restore verified until the owner enables the Drive API and a real phone uploads and restores using its Google consent. Test offline save/recovery, account switching, process recreation, token expiry/revocation, full Drive, and reinstall/new-phone restore before stable release. Main remains unmerged.
